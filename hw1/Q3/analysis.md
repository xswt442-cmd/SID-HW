# Q3 基于 TCP Socket 的分布式排序

## 实验方法

本机 Coordinator 将 16 个分组、完整输入及 Q2 排序程序打包，通过 TCP 发送。Coordinator 按 K 分配分组，使用长度前缀帧传送文件与排序结果；Worker 完成 Quick Sort 后返回有序分组，Coordinator 进行最终归并。Merge Sort 程序另行读取完整输入并生成基准文件。Worker 连接通过 SSH 隧道建立。

time-A 包含客户端打包与上传、Coordinator 解包、Worker 文件传输与排序、最终归并、结果打包、客户端下载和解包。time-B 为 Merge Sort 从读取完整输入至输出完成的耗时。

## 阶段耗时

| 阶段（秒） | K=2 | K=4 |
|---|---:|---:|
| 客户端输入打包 | 2.424 | 2.424 |
| 客户端上传 | 0.143 | 0.136 |
| Coordinator 解包 | 0.157 | 0.155 |
| Worker 上传最慢值 | 0.050 | 1.705 |
| Worker Quick Sort 最慢值 | 3.901 | 1.983 |
| Worker 下载最慢值 | 16.858 | 13.679 |
| 最终归并 | 0.618 | 0.603 |
| 结果打包 | 2.700 | 2.566 |
| 客户端下载 | 0.163 | 0.205 |
| 客户端解包 | 0.259 | 0.238 |
| time-A | 30.281 | 31.512 |
| time-B | 3.795 | 3.506 |
| time-A/time-B | 7.979 | 8.989 |

并行 Worker 阶段按最慢 Worker 统计；阶段有并行关系，不能简单相加替代 time-A。K=4 的 Quick Sort 最慢值较 K=2 下降约 49%，但 time-A 增加 1.231 秒。Worker 上传最慢值升至 1.705 秒，Worker 下载仍需 13.679 秒，数据传输抵消了排序阶段的缩短。

## 与 Q2 的比较及结果核对

| K | Q2 time-A / time-B / 比值 | Q3 time-A / time-B / 比值 |
|---|---|---|
| 2 | 36.126 / 3.797 / 9.515 | 30.281 / 3.795 / 7.979 |
| 4 | 29.557 / 3.875 / 7.628 | 31.512 / 3.506 / 8.989 |

Q3 的 K=2 time-A 比 Q2 少 5.846 秒；K=4 则多 1.956 秒。Q3 将任务打包并通过 TCP 传输，减少了 K=2 实验中逐文件 SCP 的传输开销；K=4 的 Worker 上传与下载波动仍较大。加速比同时受本机 time-B 测量值影响，因此需结合 time-A 和各阶段时延判断。Q3 K=2、K=4 的结果均有 2097152 行、升序排列，并与 Q2 基准逐行一致。运行截图分别为 `screenshots/pic3-k2.png` 和 `screenshots/pic3-k4.png`。
